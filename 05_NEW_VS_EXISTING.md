# Proyecto nuevo vs proyecto existente

## Proyecto nuevo

1. Product discovery.
2. Identificar capacidades.
3. Elegir defaults simples.
4. Decidir si usar starter.
5. Crear repo.
6. Crear primeros requirements.

## Proyecto existente

1. No modificar código.
2. Ejecutar project discovery.
3. Crear PROJECT_PROFILE.
4. Crear CAPABILITY_MAP.
5. Crear PROJECT_STATE.
6. Clasificar capacidades:
   - KEEP
   - ADD
   - WRAP
   - IMPROVE
   - REPLACE_LATER
   - IGNORE
7. Trabajar tickets con el workflow normal.

## Regla de adopción

Si una capacidad existe y funciona, el default es `KEEP`.
