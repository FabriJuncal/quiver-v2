# Atribución de consumo por actividad dentro de un trabajo

- **Origen:** corrección del usuario del 2026-09-25 al histórico por proyecto.
- **Estado:** plan v2 preparado y revisado a pedido del usuario; pendiente de
  aprobación del plan y ejecución. Ver [03_PLAN.md](03_PLAN.md).
- **Relación:** extiende el histórico v1 cerrado en
  [project-work-history](../project-work-history/06_CLOSURE.md), sin reabrir H01/H02.

Una tarea puede desarrollar una funcionalidad, corregir código, ejecutar pruebas,
documentar y explicar. El usuario no quiere elegir una única categoría para
todo el trabajo: el histórico debe medir el consumo de cada actividad según lo
que la IA haga y los archivos o pruebas que realmente cambie o ejecute.

El histórico sigue siendo prospectivo. No importar conversaciones pasadas ni
atribuir USD reales sin evidencia directa de cargo. No acceder a sesiones reales
para definir o probar este cambio; cualquier nueva fuente requerirá autorización
precisa y separada.
